# Vue3 + TypeScript：Agent 前端工程化小记

Agent 产品的前端有个特殊挑战：**状态不是静态的**。节点在跑、消息在流、任务在排队，界面要实时反映一个"正在思考"的系统。我在股票策略平台前端（Vue3 + TypeScript）里沉淀了几条经验。

## 组合式 API 组织"进行中"的状态

一个回测任务的生命周期：提交 → 节点执行（逐个状态刷新）→ 完成/失败。用 `ref` + `computed` 把任务状态机抽成可组合函数：

```ts
const { task, nodes, progress, subscribe } = useBacktestTask()
```

每个智能体节点独立维护状态与耗时，`computed` 派生出整体进度，模板只做声明式渲染，逻辑全部在 composable 里可测试。

## WebSocket：流式推送而不是轮询

节点状态与耗时通过 WebSocket 实时推送。前端做**增量合并**：服务端只发变更的节点，客户端用 `Map` 按节点 id 更新，避免整包覆盖导致闪烁。断线自动重连 + 心跳检测，重连后请求增量补拉，保证 UI 与服务端状态一致。

## 类型即文档

Agent 链路的消息结构天然复杂（文本、指标、代码片段、节点状态），我用 TypeScript 定义联合类型：

```ts
type AgentMessage =
  | { kind: "analysis"; content: string }
  | { kind: "metrics"; payload: BacktestMetrics }
  | { kind: "code"; payload: StrategyCode }
```

这样每个渲染分支都有类型保障，重构节点协议时编译器会先报错，而不是运行时才发现。

## 小结

Agent 前端不是"表格 + 按钮"，而是**过程可视化**：让用户看到 Agent 每一步在做什么、花了多久、为什么降级。把这种状态流用组合式 API 管好，前端就能真正成为 Agent 能力的放大器。
