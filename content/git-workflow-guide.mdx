# Redis 在 Agent 系统里的三处关键应用

## 多级缓存：行情毫秒级响应

行情数据的特点是**读多写极少**（一次拉取、多次查询）。我用 Redis 做多级缓存的第一级：热点股票的快照与 K 线直接走内存，命中即返回，毫秒级响应；缓存未命中才回源数据源。

```text
请求 → Redis 缓存 → Akshare 数据源 → 回填缓存
```

配合过期时间与主动失效，既保证了新鲜度，又把对数据源的请求量压到最低。

## WebSocket 心跳 + 断线增量拉取

前端与后端维持 WebSocket 长连接，Redis 记录连接心跳。断线重连后，客户端只需告诉服务端"我最后一条数据是 10:32:07 的"，服务端用 Redis 里的时间戳做增量拉取——避免整包重发，节省带宽也降低限流风险。

## 队列与限流

- **异步任务去重**：Celery 任务幂等键写入 Redis，防止重复回测；
- **接口限流**：`INCR + EXPIRE` 实现滑动窗口，保护行情数据源不被高频打到 IP 限流；
- **分布式锁**：多实例部署时用 `SET NX EX` 保证同一策略不同时跑两遍。

## 一句总结

Redis 在 Agent 系统里不是"缓存工具"，而是**状态层**：谁在线、谁跑过什么、哪个源还剩多少配额，全在这里。
