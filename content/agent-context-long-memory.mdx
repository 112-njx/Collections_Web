# Agent 的上下文压缩与长期记忆：从 30k token 上限到 72% 命中率

电商比价这个场景有个典型问题：用户会连续追问"这个到手价怎么算的""换一个颜色呢""同样的东西京东多少钱"，对话轮次一多，上下文就爆炸。在商品全网比价 Agent（AgentScope 多智能体系统）里，我把上下文治理拆成两个层面：**会话内的压缩**与**会话间的记忆**。

## 缓存断点压缩：对话再长也不爆上下文

传统做法是简单截断历史，代价是丢失关键信息。我采用的是缓存断点（Cache Breakpoint）压缩策略：

- 对话推进时，把"已完成使命"的早期轮次在**断点处压缩成摘要**，而不是直接丢弃；
- 摘要 + 最近 N 轮原文一起作为上下文，兼顾信息密度与连贯性；
- 配合**边界压缩策略**，把非关键的中间轮次进一步压薄。

实测效果：10+ 轮对话的 token 消耗稳定控制在 30k 以内，且因为压缩后的内容命中 Prompt Cache，**Cache 命中率保持在 80% 以上**——这既省了 token 成本，也显著降低了首字延迟。

## 长期记忆：让 Agent 记住上一个买家

比价用户有很强的重复性偏好：有人永远选京东自营，有人看到跨境关税就走，有人只接受三天内能到货。这些偏好只存在一次会话里太浪费。我构建了记忆检索 + 删除机制：

- **写入**：会话结束时，把买家明确表达或行为隐含的偏好（含黑名单）抽取成结构化记忆；
- **检索**：新会话到来时按语义相似度召回相关记忆，注入上下文；
- **删除**：支持显式删除，避免"用户已经说了不要，Agent 还在引用"的尴尬。

这套机制的**跨会话复用命中率达到 72%**，用户的第二次购物体验明显更"懂我"。

## 召回质量：混合召回让 Top-100 更相关

记忆和商品检索都依赖召回。单一向量召回的问题是同义表达（"性价比高" vs "便宜")和品类模糊场景容易跑偏。我做了 Query/Item 编码 + 混合召回：向量召回兜语义，关键词召回保精确，最后统一重排。改造后 **Top-100 商品召回相关率较单塔提升 22%**。

## 一点总结

多智能体系统的上下文工程，本质上是在回答三个问题：**历史里什么是必要的？什么是可以压缩的？什么是应该跨会话记住的？**

- 必要的 → 留原文；
- 可压缩的 → 断点摘要 + Prompt Cache；
- 跨会话的 → 结构化记忆 + 混合召回。

这套方法论不只适用于比价 Agent，任何长对话 + 强个性化的 C 端 Agent 产品都值得借鉴。
