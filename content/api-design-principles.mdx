# FastAPI 轻量后端工程实践：从路由到异步任务

写 Agent 类产品时，后端最重要的不是"重"，而是**快和清晰**——接口要能跟得上模型调用链路的节奏。FastAPI 在这方面非常顺手。

## Pydantic 模型即校验层

FastAPI 把请求校验内置在类型系统里：`class OrderQuery(BaseModel)` 一写，字段约束、嵌套结构、错误信息全部自动生成。省掉了 Java 里常见的"DTO + 手动校验 + 异常捕获"三件套。

## 异步优先

Agent 后端几乎全是 IO 密集：调 DeepSeek API、查 Redis、写 PostgreSQL。用 `async def` 路由 + `httpx.AsyncClient`，单机就能扛住并发模型调用；配合 `asyncio.gather` 可以并行发起多个上游请求（比如同时查多个行情源），把整体延迟压下来。

## 任务交给 Celery

策略回测这类耗时任务不能堵在请求线程里。我的做法是：接口层只负责"接单"，把任务丢进 Celery 队列，前端通过轮询或 WebSocket 拿进度。任务函数里再做进程隔离与资源限制，保证用户代码跑得再野也不影响主服务。

## 分层心得

```
routes（参数与权限） → services（业务编排） → agents（模型调用） → repos（数据访问）
```

每层只干一件事，调试模型链路时能顺着调用栈快速定位问题。这也是我在实习里升级老 OA 模块时坚持的底线——**再小的接口，也要有清晰的边界**。
