# LangGraph 多智能体实战：我把股票策略平台拆成了五个节点

做 AI Agent 股票策略平台的起因很简单：A 股股民有很多主观的交易经验，却很难把它们变成可验证、可回测的量化策略。我想做一个平台，让用户用自然语言描述自己的交易体系，由 Agent 将其转化为生产级量化代码，并一键回测、持续沉淀记忆。

## 为什么选 LangGraph 而不是纯 Chain

早期原型我用的是一串 LangChain Chain 顺序调用，很快遇到两个问题：

1. **状态无法细粒度追踪**：节点耗时、中间结论、降级原因都拿不到，用户看不到"Agent 到底在想什么"；
2. **分支逻辑难维护**：多空辩论可能出现分歧、风控可能直接否决，用 Chain 硬编码分支会越来越乱。

LangGraph 的图式编排恰好解决这两点——每个节点是一个独立函数，共享一个可序列化的 State，边可以带条件路由。我把决策过程拆成五个节点：

```text
技术分析 → 多空辩论 → 风控 → 交易决策 → 记忆沉淀
```

节点状态与耗时通过 WebSocket 流式推送给前端，任何一个节点抛异常都会自动降级（比如辩论节点失败就直接走单边分析），而不是整个链路中断。

## RAG 记忆系统：让 Agent 记住用户的交易体系

用户每次调整策略，本质上是在"教" Agent 自己的偏好。我用 RAG 把这些沉淀下来：

- **向量化**：用 ONNX 量化的向量模型把交易体系描述转成语义向量，避免大模型的推理延迟；
- **存储**：pgvector 扩展向量数据库，与业务数据同库，事务一致性好；
- **检索**：用户新对话进来时先召回历史相关记忆，注入到上下文里。

这套系统让"可修改记忆的定制交易 Agent"成为可能：用户改一条记忆，后续所有策略生成都会感知到。

## 工程化的另一半

Agent 逻辑再强，跑不动也是白搭。这个项目里我重点做了三件事：

- **多数据源防限流**：东方财富 / 新浪 / 同花顺三个 Akshare 数据源自动切换，配合 Redis 多级缓存与 WebSocket 心跳，断线后增量拉取，行情毫秒级响应；
- **安全执行**：策略代码跑在 Python 沙箱里，回测在独立子进程执行并做 CPU/内存资源限制，再用 Celery 异步队列控制并发，防止用户代码拖垮服务；
- **可观测**：Docker Compose 编排 + Nginx 反向代理，Prometheus/Grafana 监控告警，Alembic 统一管理数据库迁移。

目前项目处于开发收尾阶段，即将进入专项测试与部署运维。它教会我的最重要的一件事是：**Agent 系统的难点从来不只是模型，而是状态、记忆、执行环境与可观测性**。
